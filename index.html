Entra ID Infrastructure-as-Code

github.com/pobriendev/entra-terraform
TerraformAzureMicrosoft Entra IDAzure Key VaultGitHub Actions (OIDC)
  • Terraform that codifies, in a personal sandbox tenant, the identity layer my Graph tools need — app registration with scoped Graph application permissions and admin consent as code, a 180-day client secret in Key Vault replaced on the next apply, and remote state in Azure Storage with Entra-only auth, shared-key access disabled, versioning and soft delete, and the bootstrap step documented.
  • CI runs terraform plan on every PR through OIDC federation with a CI identity that holds no Azure write roles, and no stored credentials; plan output is redacted so the public repo and its logs expose no tenant identifiers.
  • The permissions that reset passwords and remove MFA methods sit behind a flag, off by default — a leaked secret with those can take over any account in the tenant, so they should be a decision, not a default.

Recent fixCI’s plan disagreed with mine on identical code and state: the config set each resource’s owner to whoever ran Terraform, so CI proposed making itself the owner of everything. The owner is now an explicit input. See the PR ↗

About
